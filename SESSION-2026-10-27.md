## Things that would have become mistakes

- Our deploy overwrote ENS's official `deployments/sepolia/` records. Restored;
  ours live in `deployments/sepolia-autorenew/`. Never run `deploy-v2` against
  `sepolia` without `--resume` — it ARCHIVES the existing namespace.
- `demo` found the account's `isValidSignature` swallows every validator revert
  into a generic ERC-1271 failure. Real reasons come from calling

  re-encodes those pushes. Use the metadata hash and a differential build.

## C9 — what shipping does to existing ENSv2 users

Headline is NOT "no change for everyone". It is: **no account changes unless
its owner upgrades, and an owner who upgrades invalidates every session
authorization they had already signed.**

- Upgrades need THREE consents: the DAO-held allowlist role on `UPGRADE_SET`,
  the account owner's own transaction, and the target implementation's
  predecessor gate. No path reaches an owner who does nothing.
- A non-adopter sees nothing: the new branch short-circuits on
  `renewPolicy.paymentToken != address(0)`, zero for any session that does not
  enable auto-renew.
- Reaching the new code at all needs the **owner's own signature** over a salt
  committing to a non-zero renew payment token. Not forgeable without the key.
- **The one real regression:** header 110 -> 150 bytes and salt 7 -> 10 fields
  change the derived `permissionId` even when the new fields are zero.
  Measured: `0x13925892…df4b12` vs `0xbb980c8f…5a1b2d27`. An existing live
  session stops working and the user must re-sign. State this FIRST in the ask.
- Size 18,857 bytes, **76.7% of EIP-170**, 5,719 spare. +467,600 gas once at
  deployment. Up to **+2.08%** on pre-existing operations — and `contracts`
  flagged that figure as an UPPER bound it will not defend, because the test
  totals mix calldata packing with the on-chain branch cost.

## C10 — population and whether the cost can be bounded

- The honest proposal line: "at most 354 of 2,869 have ever run an intent; how
  many hold a live session authorization is not determinable from chain data."
  Never "only N users are affected".
